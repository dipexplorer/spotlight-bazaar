# 🚨 STRICT ENGINEERING & EXECUTION RULES (MANDATORY FOR ALL AI AGENTS)

> **CRITICAL DIRECTIVE FOR ANTIGRAVITY & ANY AI AGENT WORKING ON SPOTLIGHT BAZAAR:**  
> These rules are ABSOLUTE and NON-NEGOTIABLE. They override any default AI coding tendencies, generic pre-trained habits, or rushed workflows. Every single execution across this project MUST strictly follow these 5 core mandates.

---

## RULE 1: ZERO BLIND AI SLOP & ZERO AI-DEFAULT UI/UX (USE `/impeccable` STANDARDS)
* **No Blind Coding:** Never write, modify, or delete code without first inspecting existing files, understanding the current state, and verifying dependencies.
* **Eliminate AI UI/UX Slop:** Strictly avoid generic, lazy AI-default design patterns:
  - ❌ No generic rounded floating cards with purple/indigo glow gradients.
  - ❌ No meaningless stock icons stuffed into identical 3-column feature grids.
  - ❌ No lifeless, cookie-cutter dashboard templates that look like a generic Bootstrap/AI clone.
* **Apply Impeccable Standards:** Use the `/impeccable` design principles and front-end craftsmanship:
  - High-contrast intentional typography (deliberate font pairing, tracked-out micro-labels, tight headings).
  - Purposeful palettes (deep dark charcoal/black bases, tactical single-accent neons or warm golds).
  - Micro-interactions, custom cursor physics, and responsive fluid motion that feels like an expensive human-crafted digital studio.

---

## RULE 2: ALWAYS USE LATEST MODERN TECH & GROUND IN DOCUMENTATION
* **No Outdated Stack Assumptions:** Web APIs, frameworks, and packages evolve rapidly. Never assume an old major version out of habit (e.g. Next.js 16+ is current and superior to Next.js 15; Tailwind CSS v4; React 19).
* **Verify Docs via Context7 / Live Inspection:** Before using an API, configuration option, or third-party SDK, fetch and verify current documentation. Never hallucinate deprecated properties or outdated routing conventions.

---

## RULE 3: CLARIFICATION BEFORE EXECUTION (ZERO BLIND ASSUMPTIONS)
* **Ask When in Doubt:** If requirements, edge cases, user flows, or data models are ambiguous, **STOP AND ASK**. 
* **No Silent Guessing:** Never make an unconfirmed assumption about business logic, user privacy, or core architecture.
* **Proceed Only After Approval:** Explain the ambiguity clearly, present the choices, get the user's explicit confirmation, and only then proceed with execution.

---

## RULE 4: PROACTIVELY CHALLENGE WEAK DECISIONS WITH INDUSTRY STANDARDS
* **Do Not Be a Passive Yes-Man:** If a suggested technical decision, UI structure, or architectural path is flawed, inefficient, or suboptimal, you **must speak up**.
* **Present Superior Alternatives:** Proactively present better options backed by industry standards (e.g., explaining why a lightweight Leaflet/Canvas map beats a heavy Three.js mobile bundle, or why Next.js 16+ App Router handles SSR better).
* Provide a clear:
  - **Option A (Original / Current idea):** Pros, cons, and failure points.
  - **Option B (Industry Best Practice / Recommended):** Why it performs better, scales cleaner, and converts higher.

---

## RULE 5: HIGHLY INTERACTIVE, STEP-BY-STEP CADENCE (ZERO MASSIVE CODE DUMPS)
* **Never Dump Mountains of Code in One Go:** Dumping 500+ lines of unreviewed code across 10 files in a single execution creates catastrophic bugs, hidden regressions, and unreadable slop.
* **Atomic, Incremental Execution:**
  1. Break the task into small, verifiable steps.
  2. Implement **one step cleanly**.
  3. Verify / test the step (lint, build, devtools inspect).
  4. Explain exactly what was done and present the recommended next step.
  5. Wait for the founder's review and approval before touching the next phase.
